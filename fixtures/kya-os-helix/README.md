# KYA-OS Helix fixtures

The Helix-made fixture set for the KYA-OS profile (stories rule 6): generated
once from helix-core's own implementation by
`scripts/generate-kya-os-helix-fixtures.ts` (`pnpm generate:kya-os-helix`),
checked in, and consumed by helix-core, helix-sdk-py and e2e-playwright so the
numbers live in exactly one place. The vendored KYA-OS suite itself is next
door in `fixtures/kya-os/` (see its `PIN.md`).

| File       | Story | Covers                                                                 |
| ---------- | ----- | ---------------------------------------------------------------------- |
| `jcs.json` | L1-B  | `canonicalize` / `hashJson` (RFC 8785 canonical form and `sha256:<hex>`) over sample values: key order at every depth, UTF-16 member order, string escapes, float layout, an MCP tool call's covered request and response body, an unsigned DelegationCredential and StatusList2021 credential. |
| `did.json` | L1-A  | `generateAgentKey` / `toPublicKeyJwk` / `toDidKey` / `buildDidDocument` / `resolveDid`: two test keys with seed, public key, JWK, did:key, did:web document (verification-method id `<did>#<key-id>`), the `POST /v1/agents/{did}/keys` body (public JWK only), what resolving either DID must give, base58btc vectors (L1.9) and malformed did:key cases. Generated by `scripts/generate-did-fixtures.ts` (`pnpm generate:did-fixtures`). |
| `entity-card.json` | C-A | `buildDidDocument` (with the `KyaOsEntityCard` service entry) / `buildEntityCard` / `resolveEntityCard` / `serverCardMeta` / SafeFetch: the bare-host org, an org, its org-owned agent (`responsibleParty` org, `principal` user did:key, a `revocation` entry) and its MCP service, each with DID document, card, URLs and `server.json` projection; the served map for the two-step resolution; refusals (unknown field, did:key by discovery, a card for another DID); build cases (`conformanceLevel` ignored, a proof refused); revocation cases over two test status lists; SafeFetch refusals and address classes. Generated by `scripts/generate-entity-card-fixtures.ts` (`pnpm generate:entity-card-fixtures`). |
| `jws.json` | L1-C  | `signJws` / `verifyJws` / `verifyJwsByKid`: test keys, DID documents, payloads, expected compact JWS, and the rejection cases with their reason codes. Generated by `scripts/generate-jws-fixtures.ts` (`pnpm generate:jws-fixtures`). |
| `credentials.json` | F-1 | The credential split: test keys and DID documents, a sample identity credential, an IdentityVerificationCredential, capability attestations (Helix-signed, owner-signed, one revoked in the included status list), a three-hop `DelegationCredential` chain with every attenuation-invariant refusal, `evaluateDelegationChain` results, `deriveEffectiveScopes` cases (including the retired VP verifier's formula over the golden-vector scopes), card-level cases (story C-B), and schema rejections. Generated by `scripts/generate-credential-fixtures.ts` (`pnpm generate:credential-fixtures`). |

Regenerate whenever the generating source changes and commit the diff in the
same PR. Do not hand-edit.

Who enforces it: `tests/unit/kya-os/*.test.ts` here re-derive every vector
from current source; helix-sdk-py's `tests/test_jcs.py` reads this directory
from the sibling `helix-core` checkout (or `HELIX_CORE_DIR`); the e2e spec
`tests/suite/kya-os/l1-b-canonical-json.spec.ts` runs both languages over it.
For `jws.json`: `tests/unit/crypto/jws-fixtures.test.ts` here, helix-sdk-py's
`tests/test_jws.py` (sibling checkout or `HELIX_CORE_FIXTURES_DIR`), and the
e2e spec `tests/suite/kya-os/l1-c-jws.spec.ts`. For `did.json`:
`tests/unit/kya-os/did-fixtures.test.ts` here, helix-sdk-js's
`tests/unit/agent-key.test.ts` and helix-sdk-py's `tests/test_agent_key.py`
(sibling checkout or `HELIX_CORE_FIXTURES_DIR`), and the e2e spec
`tests/suite/kya-os/l1-a-agent-key.spec.ts`.
For `credentials.json`: `tests/unit/core/credentials/fixtures.test.ts` here,
helix-sdk-py's `tests/test_credentials.py` (sibling checkout or
`HELIX_CORE_FIXTURES_DIR`), and the e2e spec
`tests/suite/kya-os/f-1-credential-split.spec.ts`.
